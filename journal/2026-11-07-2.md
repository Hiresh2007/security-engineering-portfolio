## Problems found and fixed during the session

1. **Detection gap.** First threshold was 3.5 bits/char. Checking realistic
   names showed hex-encoded *text* averages ~3.2–3.35 (random hex ~3.9), so it
   was missed. Lowered to 3.0; length and unique-count conditions keep
   single long hostnames (telemetry, blob storage) from triggering. Added a
   regression test and confirmed it fails at 3.5.
2. **Terminal escape injection.** DNS labels may contain any byte; the text
   report printed names raw, so a crafted capture could send `ESC[...` to the
   analyst's terminal. Names are now escaped (`\xNN`) in the reader; tested.
3. **Wrong test expectation.** Finding order: tunnel starts at the first
   query (T0), NXDOMAIN at the first reply (T0 + 0.01). Detector was right.
4. **Journal ordering bug** caught by the new builder test: string sorting put
   `-2.md` before `.md`.
