## Problems and decisions

- First draft filtered server replies with a port-number heuristic that only
  applied to TCP. Replaced with explicit definitions: TCP events are SYNs
  (initiator known exactly); UDP uses the lower port as the service port
  (documented assumption).
- All 77 tests passed on the first run, so the threshold was checked with a
  simulation instead of trusting the tests alone. Result: false positives
  depend mostly on the number of events, so `--beacon-min-events` is the main
  precision control.
- Known blind spot: beacons over one long-lived TCP connection.
